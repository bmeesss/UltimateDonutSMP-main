## What could not be executed in this sandbox

`mvn clean package "-Dmaven.test.skip=true"`, starting the Beast server, connecting a Java client
and an Eagler client) **could not be run here**. This is an environment limitation, not a
statement about the code:

| Requirement | Status in this sandbox |

So no `spigot-api-1.12.2-R0.1-SNAPSHOT.jar` could be resolved and no `javac` run was possible.
This matches every earlier checkpoint in `MIGRATION_STATUS.md` ("**Build not verified —
Maven/JDK unavailable**").

## What was verified instead

All of these are deterministic and reproducible from the repository:

1. **Full parse** of `src/main/java` — **424/424 files parse clean** (0 syntax errors).
2. **Bukkit class existence** — every `import org.bukkit.*` (148 distinct) resolves against a real
   1.12.2 `org.bukkit` tree (1005 classes). **0 missing.**
3. **Enum constants** — every `Material.*` (146), `Sound.*` (3), `Particle.*` (8), `GameMode.*` (4),
   `InventoryType.*` (3), `Effect.*`, `SoundCategory.*`, `DyeColor.*`, `Statistic.*` constant used in
   source exists in the 1.12.2 enum (462 `Material` constants). **0 missing.**
4. **Event handler types** — all 156 `@EventHandler` parameter types exist in 1.12.2. **0 missing.**
5. **Post-1.12.2 API calls** — a curated scan for APIs introduced after 1.12.2 found only the 8
   `SkullMeta#setOwningPlayer` sites (now fixed) and the `LeaderboardPlaceholderResolver` type
   annotation (now fixed). Everything else flagged (`sendActionBar`, `getPing`, `createBlockData`)
   was re-checked by hand and is a plugin-internal helper or a comment.
6. **ProtocolLib 5.4.0 source** for `WrappedEnumEntityUseAction`, `EnumWrappers`, `MinecraftReflection`
   and `AbstractStructure` was read from the upstream `5.4.0` tag and quoted in
   [1.12.2_RUNTIME_AUDIT.md](1.12.2_RUNTIME_AUDIT.md) §2, so the entity-use diagnosis is sourced,
   not guessed.

## Run this on the real machine

```bash
mvn -q -DskipTests compile
mvn clean test
mvn clean package "-Dmaven.test.skip=true"
ls -la target/UltimateDonutSmp-1.5.jar
```

### Post-build jar inspection — search for post-1.12.2 Bukkit references

```bash
cd target
unzip -o -q UltimateDonutSmp-1.5.jar -d jarcheck

# 1. any Bukkit class referenced by the bytecode that does not exist in 1.12.2
#    (requires a 1.12.2 spigot-api jar; point SPIGOT at it)
SPIGOT=~/.m2/repository/org/spigotmc/spigot-api/1.12.2-R0.1-SNAPSHOT/spigot-api-1.12.2-R0.1-SNAPSHOT.jar
unzip -o -q "$SPIGOT" -d spigot1122
javap -r -c -cp jarcheck $(find jarcheck -name '*.class' | sed 's#jarcheck/##; s#/#.#g; s#\.class$##') \
  | grep -oE 'org/bukkit/[A-Za-z0-9/$]+' | sed 's#/#.#g' | sort -u > /tmp/refs.txt
while read -r c; do
  [ -f "spigot1122/${c//.//}.class" ] || echo "MISSING in 1.12.2: $c"
done < /tmp/refs.txt

# 2. quick greps for the specific modern names that were removed
! grep -q 'setOwningPlayer' <(javap -r -cp jarcheck com.bx.ultimateDonutSmp.menus.StatsMenu) \
  && echo "OK: no direct setOwningPlayer reference"
grep -rl 'WrappedEnumEntityUseAction' jarcheck || echo "OK: no WrappedEnumEntityUseAction reference"
grep -rl 'org/bukkit/block/sign/Side' jarcheck  || echo "OK: no Bukkit sign Side reference"
```

## Known-risk items that only runtime can settle

* `net.kyori:adventure-text-minimessage` / `-serializer-gson` 4.14.0 are shaded into the jar and
  require Java 8+; they must not be relocated away by another plugin sharing the classpath.
* `WorthManager`'s new reverse-alias index is built lazily from `worth.yml`. With several thousand
  keys the first `/worth` or `/sell` after a reload will do one extra config walk (a few ms); it is
  cached until the next reload.
* The tablist component route now resolves `net.minecraft.server.v1_12_R1.PacketPlayOutPlayerInfo`.
  If it still cannot build a packet it disables itself **with a warning** and falls back to the
  name-preserving 16-char path — so a regression degrades the badge, never the name.
